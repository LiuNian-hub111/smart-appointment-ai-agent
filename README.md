# 物理辅导约课 Agent

这是一个面向物理辅导场景的本地学习原型。学生可以咨询课程信息、提出约课需求；系统查询老师课表，在时间冲突时推荐其他可用老师，并在用户确认后保存排班。

项目基于 [jerry-ai-dev/smart-appointment-ai-agent](https://github.com/jerry-ai-dev/smart-appointment-ai-agent) 二次改造。原项目面向按摩预约；本分支的物理辅导场景、相应代码改动与验证记录见 [改造记录](EDUCATION_ADAPTATION.md)。这不是从零开发的项目，也尚未上线。

## 为什么做

我曾担任物理辅导老师，遇到学生不了解价格、约课流程不清晰和老师排班难核对的问题。这个原型用于练习把咨询、知识检索和预约排班串成一条可验证的流程。

## 已实现的改造

- 将默认知识、咨询与任务分类提示词、演示老师资料及主要网页文案调整为物理辅导场景。
- 约课收集课程主题、开始时间和时长；老师可以由系统推荐，性别不再是必填条件。
- 保存前再次检查同一老师的时间冲突；保存成功后才返回“约课成功”。冲突时可推荐其他老师，待用户确认后再保存。
- 修复知识录入接口，支持问答或自由填写内容，并拒绝空字符串与纯空格内容。
- 常见价格和约课流程问题直接读取本地知识库；明确的“我想预约……”请求由本地规则分类。日期、时间、时长和课程主题都写清楚的演示约课可在本地提取信息；其他咨询和模糊约课仍会调用模型。

## 运行

已在 Python 3.12 下验证；运行还需要项目依赖，以及可用的聊天模型和 Embedding 模型 API。密钥只放在本地 `.env`，不要提交到仓库。

Windows PowerShell 示例：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

在 `.env` 中填入所选服务商的 `MODEL_PROVIDER`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`，以及 Embedding 对应的配置。然后启动：

```powershell
.venv\Scripts\python.exe app.py
```

访问：

- 聊天页面：<http://127.0.0.1:8001/>
- 知识库页面：<http://127.0.0.1:8001/knowledge>
- API 文档：<http://127.0.0.1:8001/docs>

默认知识库中的价格、上课方式和取消规则均标为“未确认”。如需演示具体价格，可在知识库页面编辑“课程价格”条目，并明确标注“演示价格”；不要把示例金额当作真实报价。

## 验证结果

离线测试命令：

```powershell
.venv\Scripts\python.exe -m pytest tests -q
```

本地运行结果：**18 passed，6 warnings**。测试覆盖旧数据库迁移、知识接口输入校验、知识写入与读取、常见问题快捷回复、明确预约意图分类、完整演示约课的本地信息提取，以及同一老师的重叠时间冲突。并发测试使用两个独立数据库连接：第一笔写入未提交时，第二笔等待；提交后第二笔识别冲突。

另外完成过一次本地网页联调：先将演示老师 A 的 `2026-12-01 15:00–16:30` 保存为 `busy`；再请求老师 A 的 `15:30–16:30` 时，系统识别冲突并推荐演示老师 C。用户确认后，数据库新增老师 C 的预约，老师 A 没有第二条重叠记录。演示数据保存在本机数据库中，不随仓库提交。

完成老师命名与数据库迁移后，又通过聊天接口预约演示老师 B 在 `2026-12-02 15:00–16:00` 的电磁学课；接口返回约课成功，数据库查到对应 `busy` 记录。该次请求约耗时 18 秒，时间会受模型服务状态影响。

定位耗时后，为信息齐全的演示约课加入本地解析。再次通过聊天接口预约演示老师 B 在 `2026-12-04 15:00–16:00` 的电磁学课，约 0.23 秒返回成功，数据库存在对应 `busy` 记录。这是单次本地测量，不代表所有预约都能达到此速度。

## 当前限制

约课确认接口 `POST /api/bookings/confirm` 支持请求编号防重复，输入示例：

```json
{"request_id":"lesson-001","teacher_id":1,"start_time":"2026-12-06T15:00:00","end_time":"2026-12-06T16:00:00","course":"高中物理"}
```

同一次操作重试必须复用 `request_id`；相同编号和内容返回首次保存的结果（含同一个 `schedule_id`）。同一编号改内容或不同编号抢已占用时段返回 409。请求回执与排班在同一事务提交，失败一起回滚。无时区的时间按北京时间解释。该接口可在重启服务后的 `/docs` 中试用；当前共享单用户。网页聊天会先生成约课确认卡片；点击确认才调用此接口。卡片在同一浏览器标签页保存请求编号和内容，失败后点击重试复用编号，刷新页面也能恢复未确认卡片。重新发送聊天消息会生成新卡片，不等同于重试；请使用原卡片的重试按钮。暂不支持该接口创建的预约的取消与回执失效处理。

新增确认接口后完整离线测试结果为 **23 passed，7 warnings**；包含持久化重试、竞争提交、编号冲突、参数校验和提交失败回滚。上述 18 项结果为前一阶段记录。

- 老师 A/B/C 是演示资料；真实价格、授课方式、地点和改期规则尚未配置。
- 开放式咨询及预约信息提取依赖模型服务；服务商限流时可能等待较久或失败。
- 本地快速解析目前只覆盖显式日期、时间、时长和少量演示课程主题；信息模糊或指定非演示老师时回退模型。
- 当前为本地原型；网页对话状态已按对话 UUID 隔离，但尚无登录身份校验、对话归属验证或知识管理权限控制。
- SQLite 保存 `busy` 排班时先取得写入锁，再检查冲突和保存；已通过两个连接的竞争测试。尚未做多进程压力测试，也未验证其他数据库的并发行为，不适合直接用于大规模线上约课。
- 原有本地数据库会在启动时迁移为 `teachers` / `teacher_schedules`；迁移前建议备份数据库。`strength` 等少量数据库字段沿用旧结构，含义在本项目中是教学专长。

原项目的架构说明与完整历史可在[上游仓库](https://github.com/jerry-ai-dev/smart-appointment-ai-agent)查看。

网页确认阶段验证：24 项 Python 离线测试通过（7 条弃用警告）；`node tests/booking_ui_retry.cjs` 验证实际页面脚本在确认回复丢失后重试仍使用同一编号和内容。尚未完成真实浏览器与模型服务的完整联调。以上 18 / 23 项为前阶段结果。

对话隔离阶段：网页每次加载生成新的 `conversation_id`，本页后续消息复用它，清空聊天时换新编号。后台按编号建立独立 Agent 和历史记录，同一对话串行处理。状态仅存于单进程内存，最多 128 个对话，超限需重启本地服务；重启会丢失历史，刷新页面开始新对话。UUID 不是登录凭证，不具备访问权限保护，多进程部署仍不受支持。27 项 Python 离线测试通过（7 条弃用警告），网页约课重试脚本通过；会话测试使用替代 Agent，尚未完成双网页与真实模型联调。

会话记忆阶段：约课进度、当前流程、最近 40 条预约解析消息和用户显式课程偏好保存到 SQLite 的 conversation_memories 表。网页同一标签页刷新会保留对话 ID，服务重启后可恢复；点击清空会新建对话，但不会删除旧对话的数据库快照，复制标签页可能继续同一对话。不是完整聊天记录浏览功能，也没有跨用户的长期记忆。可输入“记住课程偏好：高中物理力学”“查看记忆”“忘记课程偏好”。偏好仅在本对话缺少课程时补充默认课程，明确的本轮输入优先，不填充日期、不跳过冲突检查或最终确认。无登录和归属校验，仅限本地演示；快照目前无自动过期清理，不支持多进程同时改同一对话。29 项离线测试通过（7 条弃用警告），另有网页重试脚本通过。上述内存不持久化的限制为前阶段记录，当前以本段为准。

用户记忆阶段：本地演示使用服务器固定身份 local-demo-user。课程偏好存入 user_memories 表，按 user_id 读取；新对话共享此演示账号的偏好，约课状态仍按 conversation_id 隔离。查看、修改、忘记课程偏好会读取或更新用户记忆；已有对话下一次请求可看到变更，已填写的本次约课内容不自动覆盖。旧版对话快照中的偏好不自动升级为用户偏好，需明确重新保存；旧快照不会自动清理。没有登录认证，所有页面都是同一个演示用户，不能作为多人身份隔离方案。30 项离线测试通过（7 条弃用警告），网页重试脚本通过；跨对话记忆使用替代 Agent 测试，不依赖模型调用。前文仅对话内偏好记忆为历史阶段说明。

自动记忆阶段：对含自述等候选词的消息，使用聊天模型额外提取 course、learning_need、availability；限制为本人稳定学习事实，要求原文片段依据，临时/第三方等部分表达由保守规则整体跳过。采用固定字段合并更新，可更新稳定时间限制，咨询生成会读取这些字段作为参考。常见自然语言“忘记偏好”“你还记得我什么”“忘记我的时间偏好”支持快捷处理；更复杂表达受模型判断和候选词覆盖限制，并非完整自由语言理解。额外模型请求最长等待约 7 秒，不重试，失败不写新记忆，正常聊天继续。34 项离线测试（7 条弃用警告）及网页重试脚本通过；提取测试使用替代模型，真实智谱联调遇到 RateLimitError，尚未验证真实提取效果。仍是共享演示账号，无登录认证。未实现长对话摘要或任意历史语义检索。历史快照可能保留旧偏好字段，但实际用户记忆每轮由 user_memories 重新读取；遗忘命令不是全库历史数据清除。
